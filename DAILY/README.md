# Informe de Daily Scrum · SI-988 Soluciones Móviles II

El **Scrum Master** de cada equipo registra aquí lo que ocurrió en la sesión de
15 minutos. Se entrega **un informe por cada Daily Scrum**.

> **El Daily Scrum no es este informe.** La *Scrum Guide 2020* define un evento
> de 15 minutos, **de los Developers y para los Developers**, para inspeccionar
> el avance hacia el Sprint Goal y adaptar el plan del día. Convertirlo en un
> reporte de estado al Scrum Master es la deformación que señala la teoría de la
> [Semana 03](../SEMANA-03/1-TEORIA.md). Este documento **se escribe después del
> evento**, y existe porque el curso necesita evidencia de que el equipo lo
> sostiene y de qué aportó cada integrante.

| Documento | Para qué |
|---|---|
| [SI988-MODELO-INFORME-DAILY.docx](SI988-MODELO-INFORME-DAILY.docx) | El modelo que se llena. Ocho secciones y su rúbrica |
| [SI988-EJEMPLO-INFORME-DAILY.docx](SI988-EJEMPLO-INFORME-DAILY.docx) | El mismo modelo resuelto, con la App 01 del catálogo y un equipo ficticio |

También quedan las versiones en Markdown
([modelo](SI988-MODELO-INFORME-DAILY.md) ·
[ejemplo](SI988-EJEMPLO-INFORME-DAILY.md)) para leerlas desde GitHub sin
descargar nada.

## Cómo se nombra el archivo

```
SI988-S<NN>-DAILY-<DD>-Grupo<N>.pdf      ejemplo: SI988-S05-DAILY-02-Grupo4.pdf
```

`<NN>` es la semana con dos dígitos, `<DD>` el número del daily dentro de esa
semana y `<N>` el número del grupo.

## Qué se entrega y cuándo

| | |
|---|---|
| **Quién lo escribe** | El Scrum Master del sprint, que **rota cada dos sprints** |
| **Formato** | PDF exportado desde Word. No se entrega el `.docx` |
| **Cuándo** | Dentro de las 24 h siguientes al Daily Scrum que registra |
| **Dónde se sube** | Aula virtual, tarea «Daily Scrum · Semana NN» |
| **Copia en el repositorio** | `docs/sprints/SPRINT-<N>/dailies/daily-<DD>.md` |

## Los cinco sprints del semestre

| Sprint | Semanas | Quién es Scrum Master |
|---|---|---|
| **1** | 01 a 03 | El primero que designa el equipo en la Semana 01 |
| **2** | 04 a 06 | El mismo. La rendición de cuentas rota cada dos sprints |
| **3** | 07 a 09 | El segundo |
| **4** | 10 a 12 | El mismo |
| **5** | 13 a 16 | El tercero |

> El reparto de sprints de cada aplicación está en la ficha de su dominio, en
> [CATALOGO-APPS](../CATALOGO-APPS/README.md). El equipo que propone su propia
> aplicación define el suyo con la misma estructura.

## Lo que más se descuenta

1. Un avance declarado **sin su *issue* ni su Pull Request**. Lo que no se puede abrir no se puede dar por hecho.
2. Un integrante ausente al que se le **inventa un avance**.
3. Un impedimento **sin responsable ni fecha**, que está mencionado pero no registrado.
4. Un informe escrito el domingo **con lo que muestra el tablero**, no con lo que se dijo en la sesión.
5. El tablero que **contradice** al informe. El docente mira los dos.
